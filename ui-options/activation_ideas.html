Better activation for card and bank transfer: ideas first

Visual ideas only. Nothing is built in Figma. Each idea shows what changes, what the three sources would say (design-taste, ui-ux-pro-max, ant-design), and whether it needs a new component or can be composed from Pay Design System V2. These come from reading the flows, not from usage data, so treat them as hypotheses to test.

1 · Say the effort on the button

Today the button only says "Accept card payments", so people cannot tell whether it is one click or a form. Say what is coming, using what we already know about the account.

design-tasteOne primary action per tile, and the label should be a verb plus an object. Effort next to the action costs nothing and removes the surprise.
ui-ux-pro-maxProgress indicators: show the number of steps before the user starts. Redundant entry (WCAG 2.2): do not ask again for what is on file, so skip the industry step.
ant-designSteps: when a task has a sequence, say so up front.
No new componentCopy and logic on the existing tile. It matches the C2b frame you already have (Adyen terms only, industry on file). Do not state a time for card until engineering confirms one.

design-tasteExhaust inline and progressive options before reaching for a modal. Nested cards are wrong, so the terms are a bordered row, not a card in a card.
ui-ux-pro-maxOnboarding user freedom: easy to back out (Cancel). Forms: label above the field, one primary button. Loading state on the button after click.

Existing component, new behaviourPay Design System V2 already has an Accordion, plus the Text field, Select and Card / Checkbox used in the current modal. The work is composing them inside the tile. Trade-off: the tile grows and pushes the setup list down. Test it against the modal, because the terms wording is still pending.

design-tasteReplace the generic line with a specific, real number. Avoid fake-perfect figures, so use the account's actual rate.
ui-ux-pro-maxContent: say what the user gets in their terms. Keep copy short enough to stay on one line at narrow widths.
ant-designStatistic-style emphasis: a number the user can picture beats an adjective.
No new componentCopy only, with the rate read from "Your rewards". Flag: the hero card shows +3,000 points on a $1,000 invoice while "Your rewards" says 2 points per $1. One of them is wrong, and this idea makes it visible.

4 · Show where an activating method is up to

"Activating" with no detail makes people refresh. A three-step line shows it is moving, and the email promise is the way out. Bank is active within about a minute, but the email can arrive up to 30 minutes later, so do not promise the email is instant.

design-tasteMake the state legible: skeleton or progress that matches the final layout, not a bare label. Motion only to convey state (the dot pulses once).
ui-ux-pro-maxProgress indicators and loading: state the expected wait. Never leave a long wait unexplained. Announce status changes with a polite live region.
ant-designSteps and Result: a sequence needs steps, and a finished outcome needs a clear result.
Existing componentPay Design System V2 has a Stepper (with Stepper/Step and StepConnector). A compact three-dot version may need a small variant. Confirm the timing wording with Anh first.

design-tasteEmpty and success states should teach the next step. The accent is for the one primary action, so only the first visit gets a filled button.

6 · Not recommended: a switch to turn it on

It looks tidy, and it would pair with the turn-off flow. But a switch changes state the moment it is flipped, and turning card on needs terms and details first.
CardOff
Visa and Mastercard on invoices you create in pay.com.au
Earn PayRewards Points on every payment
A switch promises an instant on and off. Card on needs the industry and the terms, so the switch would flip, then open a modal, then maybe flip back. The user sees a control lie to them.
design-tasteDo not reinvent a standard affordance with a different meaning. A switch is for instant, reversible settings.
ui-ux-pro-maxConfirmation dialogs: confirm before irreversible actions, which turning off is. A bare switch skips that.
ant-designSwitch vs Checkbox: a switch triggers the change directly, a checkbox needs a submit. Activation needs a submit, so a switch is the wrong control. Its inline label should read Enable/Disable.
SkipKeep "Turn on" as a button. A switch could suit "Turn off" later, once activation is done, but only with the confirm modal already designed.

Component or not?

Short answer: almost none of this needs a new component. Ideas 1, 3 and 5 are copy and state on the tile you already have. Ideas 2 and 4 reuse Accordion and Stepper from Pay Design System V2. Decide on a component only after one of these wins a test.
